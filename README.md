# saas-billing — SaaS の課金システムを作る人のための Claude Code スキル

サブスク課金（月額の有料プラン、カード決済、請求書払い）を SaaS に付けるときの、設計・決めること・状態遷移・実装の罠・テスト台帳・規約・既存ユーザーへの出し方を、Claude Code のスキルとしてまとめたものです。Pay.jp を主に、Stripe で違うところは並記しています。日本語です。

もとになったのは、HANAMII株式会社が自社サービスにカード決済のサブスク課金を付けたときの経験です（2026年8〜9月。仕様の改訂12版、独立レビュー2巡、ストーリー検証99本、テストケース91件の本物環境での再現、規約24社の比較、既存ユーザーへの周知計画）。サービス固有の価格や件数は外し、手順と判断の型だけを残しています。

## 入れ方

Claude Code のスキルは `SKILL.md` を含むディレクトリです。次のどちらかに置きます。

```bash
# 全プロジェクトで使う
git clone https://github.com/hanamii-sakura/saas-billing-skill ~/.claude/skills/saas-billing

# 特定のプロジェクトだけで使う
git clone https://github.com/hanamii-sakura/saas-billing-skill <project>/.claude/skills/saas-billing
```

入れたあと、Claude Code で「課金つけたい」「有料プランの仕様を決めたい」「課金のテストケースを出して」のように頼むと、このスキルが読まれます。読まれない場合は `/saas-billing` と打つか、「saas-billing スキルを使って」と添えてください。

## 使い方の例

- 「Pay.jp で月額の有料プランを付けたい。無料プランはアプリ2本まで。設計方針と決めることを整理して」
- 「解約と支払い失敗まわりの仕様を決めたい。督促は何日、いつ止めていつ消すか、規約に何を書くか」
- 「この Prisma スキーマと service に対して、課金のテストケースの台帳を作って」
- 「有料プランを既存ユーザーに出す計画と周知メールを作って」

## 向いていないこと

- 従量メータリング（秒単位・リクエスト単位）が中心の課金。この資料は「月額＋枠」の前払いモデルが軸です
- Stripe Billing にサイクル管理まで全部預ける構成。預ける範囲の考え方は書いていますが、Stripe Billing の設定手順は書いていません
- 大量トラフィックの B2C（数万件の同時決済）。同時実行の話は B2B・セルフサーブ規模の実測です

## 注意

- 数字（猶予日数、再試行の間隔、レート制限、返金可能期間）は 2026年9月時点の例です。自分のサービスと PSP の公式ドキュメントで確かめてください。
- 規約の章は法律の助言ではありません。弁護士に持って行くときの整理として使ってください。
