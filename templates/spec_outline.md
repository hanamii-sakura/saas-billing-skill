# 課金機能 仕様書の章立て

12版まで改訂した仕様書が最終的に持っていた章。最初から全部埋めなくてよいが、章の見出しだけは最初から置いておくと「まだ書いていない」が見える。

1. 概要とスコープ（段階の分け方／扱わないこと）
2. 用語と現在の構造（現状の実装と変更点／コードで確認した現状）
3. ユースケース一覧
   - 組織とアカウント
   - 支払い方法
   - 契約
   - 第三者による支払い（委任）
   - 請求・経理
   - 既存ユーザー・既存契約の移行
   - 支払い失敗と回収
   - 運用と計測
4. 設計方針と根拠（課金がどこにぶら下がるか）
5. データモデル
   - 新規テーブル
   - 既存テーブルの変更
   - **時計の規約: どの操作をどの時刻で判定するか**（`references/01_frameworks.md` F2）
6. 契約の状態遷移（状態の補足規定。`references/03_state_machines.md`）
7. 主要フロー
   - 有償化
   - 支払い失敗からの復帰
   - 第三者による支払い
   - 解約と取り消し
   - 既存ユーザーの移行
8. API 一覧（決済用の認証パターン）
9. 画面一覧（モックとの対応）
10. 非機能・法令
    - Webhook の認証
    - **冪等性と二重課金の防止**
    - 秘密情報の扱い
    - 公開エンドポイントと通知
    - 法令・表示（特商法、インボイス）
    - 経営指標との接続（MRR、解約率をどこから取るか）
11. レビューしてほしい論点
12. 実装順序（作成するファイル）
13. 未確認事項
付録: 将来構想（凍結した仕様の置き場。消さずにここへ移す）

改訂履歴は文書の末尾に置き、冒頭には最新版の要約を置く。
