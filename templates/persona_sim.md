# ユーザー役シミュレーションの雛形

周知文面を出す前に、実データの区分からペルソナを作り、複数のモデルに演じさせて、審判役が判定する。`references/07_rollout.md` 6章の手順。

## 1. world.md（唯一の事実）

```
# 世界の事実（コードの実挙動どおりに書く）
- サービス名 / 無料プランの範囲 / 有料プランの価格と含まれるもの
- 公開日 D、期限 E、停止日 E+1 の 0時台
- 期限までに起きること: 何も止まらない。新しい操作だけ拒否される
- 期限後に起きること: 超過分が停止する。データは残る。URL は変わらない / 変わる
- 契約したときに起きること: 停止していたものが自動で再開する / しない
- 画面の文言: 拒否画面・契約ダイアログ・バナーの実際の文
- 送られるメール: 件名・送信日・本文の要点（全員向け / 超過向け / 停止翌日）
- 過去の告知: いつ何を言ったか（矛盾があればそれも事実として書く）
- 決まっていないこと: 「未定」と明記（ペルソナに推測させない）
```

## 3. プロンプトの縛り（各ペルソナに渡す）

```
あなたは personas.md の {ID} です。world.md に書いてあることだけを事実として扱ってください。
- 自然に反応してください。わざと怒ったり、わざと褒めたりしないでください。
- world.md にないことは事実にしないでください。分からなければ「サポートに聞く」と書いてください。
- 日記形式で書いてください。
  1. メールを読んだ直後
  2. ログインして画面を見たとき
  3. 補足メールを受け取ったとき
  4. 停止日
  5. サポートへの問い合わせ（送るなら全文）
  6. 最終的な行動
  7. 言いたいこと（3つまで）
- 最後に1行: SUMMARY: {ID} | 理解度(高/中/低) | 気持ち(一言) | 最終行動 | 一番の引っかかり
```

複数のモデルに分けて演じさせると、同じ文面でも引っかかる場所が変わる。

## 4. 審判の観点

```
world.md と各ペルソナの出力を読んで、次を出してください。
1. 事実を取り違えて損をした人（誰が、どの文のせいで）
2. 同じテーマで引っかかった人数（テーマ別）
3. 直すもの
   a. 文面の直し（重要な順、直した文案つき）
   b. 文面では解けない「決めること」の一覧
   c. ペルソナの演技上の推測で、対応不要なもの
4. 追加する FAQ（質問と答え）
5. やること上位5つ
6. 全体の判定: 支持 / 条件つき支持 / 出し直し（理由）
```
