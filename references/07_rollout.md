# 07 既存ユーザーがいるところに課金を出す

この資料で決まること
- 課金の壁が「効く」3つのタイミングと、同じ日に出すべき理由
- 既存ユーザーを区分して、誰がいつどうなるかを表にする方法と人数の数え方
- 公開日 D と期限 E を軸にしたタイムライン、周知の設計、当日の手順
- 周知文面をユーザー役のシミュレーションで叩く方法と、問い合わせを生む要因

不利益変更の周知は、日付とコードの実挙動が一致していないと信用を失う。文面の日付・環境変数の日付・ジョブの境界の3つを揃えてから出す。

---

## 1. 課金の壁が効く3つの段階

1. **コードを本番に出した瞬間**: サーバー側の上限判定（2本目のリソース、招待、独自ドメインの拒否）は、画面のフラグと無関係に有効になる。定期ジョブも動き出す。
2. **画面フラグを ON にした瞬間**: 契約の入口（料金ページ、契約画面、ダイアログ）が開く。ビルド時にフラグを焼き込む方式なら再デプロイが要る。
3. **移行期限の日**: 無料プランの範囲を超えた分が停止する。

①と②の間が空くと、**拒否だけがあって契約の出口がない**期間ができる。**同じ日に出す**のが推奨。分けるなら、課金スケジューラを止めるフラグ（`DISABLE_BILLING_SCHEDULER` など）を別に用意する。

---

## 2. 区分×影響の表

行はユーザーの区分、列は ①出した日／②フラグ ON／③期限日／その後。

| 区分 | 押さえること |
|---|---|
| 無料・上限以内 | 何も止まらない。新しい操作だけ拒否される |
| 無料・上限超過 | 期限と、止まるリソースを名指しした表示。何を残すか本人が選べる |
| 無料・メンバー超過 | いるメンバーはそのまま。新しい招待だけ拒否 |
| 無料・独自ドメインあり | 既に設定したドメインは動き続ける。ただしリソースが止まればドメインも同時に止まる（「14日の猶予」と書いてあったが実装は即時遮断だった、という食い違いに注意） |
| 旧来の有料契約（個別契約・請求書払い） | すべての対象外 |
| 保留中の法人申込 | 個別に連絡する |
| 社内アカウント | 除外リストで管理し、一斉メールから外す |

人数は本番のデータから数える。API が一覧を上限件数で打ち切るなら、その旨を表に書く。**別の仕組みで停止中のリソースも本数に数えるか**を必ず確認する。

---

## 3. タイムラインの型

公開日を D、期限を E とする。猶予は「D＋2か月」のように決め、E は「その前日」にすると説明が楽。

- **D−14**: D と E を決める。環境変数（PSP の本番鍵、SMTP、ジョブのトークン、通知先、運営画面の許可リスト）、本番 Webhook の登録、本番 DB の実数を揃える。**リポジトリ変数に古い期限が残っていないか確認する**（8月に仮置きした日付が10月にそのまま有効になっていた例がある）。
- **D−7**: 文面を最終化し、差し込むデータ（本数・名前・金額）を用意する。
- **D−5**: 保留中の申込に個別連絡する。
- **D−1**: ブランチを取り込み、ステージングで人が実際の Checkout を1回通す。フラグを切り替える。
- **D**: デプロイ、ジョブの動作確認、一斉メール、差し込みメール、アプリ内のお知らせ。
- **D+1 以降**: 毎朝、前日のジョブが成功したかを SQL で見る。**ジョブが止まっても通知は何も来ない**前提で見る。
- **E−30／E−7**: 自動メール（猶予が30日未満なら30日前の分は出ない。当日ジョブ限りで翌日再送もない）と手動の補足。
- **E**: その日の 23:59 まで無料。停止は **E+1 の 0時台**（「当日の 0時台に止まる」バグに注意。03 の日数一覧）。
- **E+1**: 停止メール、集計、失敗分の手動停止、契約した人の自動再開。
- **E+31 前後**: 止めたリソースが、無料プランの放置停止（別制度）に巻き込まれないか確認する。

---

## 4. 周知の設計

**手段**: 一斉メール／コードが送る自動メール（SMTP が空だと全部失敗する。送信テストを先にやる）／アプリ内のお知らせ／料金・お知らせ・ガイド・規約のページ。

**全員向け**: いまの利用は変わらない、手続きは要らない、勝手に有料にならない、変わるのは N 点だけ。**対象外の人に「対象外です」と言う**（条件を読んで一瞬迷う人が多い）。

**超過している人向け**: 共通の説明に続けて「あなたの状況」を置く2部構成。本数、期限までは全部動くこと、どれが止まりどれが残るか（名前で）、選べる3つの道（払う／減らす／何もしない）、合計金額。

**旧来の契約者向け**: 何も変わらないこと。加えて「新しい安いプランと何が違うのか」の一段落（担当者が社内で聞かれる）。

**停止した翌日**: 止めたもの・残したもの、データは残っていること、申し込めば同じ URL で自動再開すること、勝手に課金しないこと、**金額と申込先 URL**。一番切迫した場面で読まれるメールなので、情報を削らない。

**文面は実装と照合する**: 既存の告知文を再利用するときは、1文ずつコードの挙動と突き合わせる。**文面の日付と環境変数の日付を必ず一致させる。**

文面の骨は `templates/notice_outline.md`。

---

## 5. 当日の手順

**公開日**: 環境変数と secrets を名前で確認（値は見ない）→ マージ → デプロイのワークフローを確認 → 15分以内にジョブの実行記録を確認 → 自分の無料アカウントで拒否画面から契約ダイアログまで確認 → ページを目視 → 送信（旧来の契約者と社内は除外）→ 監視チャンネルを決める。

**期限日の翌朝**: 停止の集計を見て、失敗があれば手動で停止する。停止メールが届いたか確認し、届いていなければ手で送る（自動メールは再送されない）。「戻らない」と言われたら契約と枠を確認して手動で再開する。「どれが止まったか」は選定の記録（監査用 JSON）で答える。

---

## 6. ユーザー役のシミュレーション

周知文面を出す前に、実データの区分から10人前後のペルソナを作り、複数のモデルに演じさせて、審判役が判定する。雛形は `templates/persona_sim.md`。

**入力**
- `world.md`: サービス側で実際に起きることを、コードの実挙動どおりに書く。日付、料金、画面の文言、停止後の挙動、過去の告知まで。**これを唯一の事実にする。**
- `personas.md`: 人物・状況・受け取るメールの表。例: 流し読みする趣味の人／納品物を持つフリーランス／全部放置している人／稟議が要る会社員／メンバーがいる制作会社／独自ドメインでポートフォリオを出している人／旧来の契約者／返事を待っている法人申込者／メールを開かない人／疑り深い開発者。

**プロンプトの縛り**: 自然に反応する（わざと怒ったり褒めたりしない）／world.md にないことを事実にしない（分からなければ「サポートに聞く」）／日記形式（メールを読んだ直後、ログインして画面を見たとき、補足メールを受け取ったとき、停止日、サポートへの問い合わせ全文、最終的な行動、言いたいこと3つまで）／最後に1行 `SUMMARY: ID | 理解度 | 気持ち | 最終行動 | 一番の引っかかり`。

**審判が見ること**
- world.md と照らして、事実を取り違えて損をした人がいるか
- 同じテーマで引っかかった人数
- 直すものを3種類に分ける: 文面の直し（重要な順）／文面では解けない「決めること」の一覧／ペルソナの演技上の推測で対応不要なもの
- 追加する FAQ
- やること上位5つ
- 全体の判定（例: 条件つき支持）

**問い合わせを生む要因（10人で実際に出た順）**
1. 会社・経理まわり（法人カード、少額の請求書払い、インボイスや領収書、返事のない申込）。10人中4人
2. 新しいプランの中身（メンバー数、「作る」と「公開する」のどちらで止まるか、旧来契約との差）
3. 対象外の人が条件を読んで一瞬迷う
4. 別の停止制度（放置停止）との混同
5. 一番切迫した場面で読まれる停止メールの情報不足
6. 何を残すかがいつ決まるか（納品物が止まる危険）
7. 決済失敗、返金、カード情報の保管先
8. 「見るだけで課金されそう」で契約画面を押せない

シミュレーションで出た指摘は、文面だけでなくコードにも戻す（停止翌日のメールが無かった、残すリソースを固定する操作が無かった、など）。

---

## 7. 出す前の最終確認（リリース可否）

5つの観点で、別々の担当（またはエージェント）に見せて判定を揃える。
1. お金の正しさ（二重課金・期間重複・税計算・表示と請求の一致）
2. 運用の準備（環境変数・secrets・Webhook 登録・ジョブ停止の検知・既存有料顧客の免除フラグ）
3. 法律の表示と規約（特商法ページ・インボイス登録番号・規約の版と同意記録）
4. 既存ユーザーと出し方（この資料）
5. セキュリティ（委任メールの宛先検証と回数上限、運営画面の認可、Webhook 認証）

出力は「直すコード（重い順）／用意するもの／決めること／テストの実施状況／確かめられなかったこと」。判定は「出せる／条件つきで出せる／出せない」の3値。前回の判定との差分を章にすると、2回目以降が短くなる。
